獨立技術架構與工作量

本次實作

theatre-preview/ 是獨立靜態頁：HTML／CSS／JavaScript ES modules，沒有新增或重建 Vite 專案、沒有安裝應用依賴，也沒有匯入 React／Phaser 正式遊戲入口。

  • story.mjs：版本、角色、六次決策、條件回應、虛構支出、記憶、八結局與法律pending封套。純函式、無隨機數。
  • app.mjs：閱讀流程、逐段對話、選擇、結局、回顧、基本法律知識與單一說明視窗。
  • theatre.css：回應式視覺小說布局、三字級、可捲動面板、觸控與焦點樣式。
  • story.test.mjs：邏輯測試；這些不是法律計算已核實的測試。
  • assets/：原創AI概念素材與來源狀態。
  • docs/：規格、分支圖、結局條件、路線、法律待查與驗收。

資料只在頁面記憶體中。無 cookies、localStorage、IndexedDB、帳號、Supabase請求、分析事件或service worker註冊；重開只重置本頁run。重新整理會失去原型進度，已明確告知。既有 State v4 與瀏覽器遊戲存檔鍵完全不碰。

schemaVersion:1 是原型敘事資料版本，不是經營模式 State v4 的升級或遷移。對話串可合流，但run.choices、ledger、memories、documents保留；legalResults始終空。

事件與法律分離

玩家選擇 → 敘事狀態／虛構支出／客觀事實／主觀記憶
                 ↓
          後續條件台詞與敘事結局
                 ↓
     法律封套（日期、待查事項、官方來源）
                 ↓
     尚無 approved 規則 → pending，不計算

父、母各有獨立estate ID、死亡日期與未分配清冊，沒有共用一筆「父母遺產」。人物情感不傳入法律比例。固定路由可重現，沒有抽籤式司法結果。

正式開發建議（先等方向確認）

  • 沿用現有 React／TypeScript，新增隔離的 TheatreRenderer 與純 TypeScript story engine；Phaser經營城市不必在此模式啟動，減少下載與生命週期耦合。
  • 內容以版本化JSON／受驗證的型別編輯，先做簡單驗證CLI與Git差異審查，不急著做大型後台。
  • 規劃型別：VolumeDefinition、SceneNode、DialogueNode、DecisionNode、Consequence、Memory、EndingDefinition、LegalEventEnvelope、ApprovedRuleReference、NarrativeRun。
  • 法律adapter唯讀讀取經審核規則bundle與版本雜湊；法律未過關的分支保留pending，禁止內容檔直接寫入稅額或生效旗標。
  • 正式存檔另用 theatre-profile-v1／獨立雲端表與run ID；每卷釘選contentVersion，維護者決定舊內容相容策略，不遷移正式GameState v4。
  • 結局圖鑑、勳章、歷次重玩紀錄列為後續；不以本次記憶體陣列冒充永久成就。
  • 圖像換成分件立繪、表情manifest、背景與行動裝置安全區；WebP/AVIF、資產預載與失敗fallback、 reduced-motion與實體Safari驗證列入正式製作。
  • 無障礙：鍵盤完整走卷、語意化對話／決策、讀屏朗讀節奏及實體觸控須人工測試，不能只靠DOM或對比數值認證。

發布隔離

此原型放在 /family-wealth-empire/theatre-preview/，不改首頁經營入口、既有UI預覽與State v4。獨立預覽發布沿用已上線遊戲產物並比對雜湊，只追加預覽目錄；不重新建置正式遊戲或發布工作區未提交的教學程式。

目前預覽的一次性部署機制仍釘選舊產物，若正式遊戲變更就應停止並以新基線重新驗證；不可用來回滾新遊戲。未改正式SW，也不承諾本原型離線可用。日後正式遊戲部署若要保留此目錄，需明確納入其發布規劃。
